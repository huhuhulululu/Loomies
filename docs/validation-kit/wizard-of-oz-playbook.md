# 方法① Wizard-of-Oz 管家测试 · 操作手册

> **核心方法**：零代码测「他们要算法决定还是自己规划」这个精确赌注。你（创始人）当「算法」，每晚手动发次日穿搭，测**揭示行为**（非陈述偏好）。
> 成本 ~$0（+ 可选礼卡）；周期 1-2 周；样本 8-12 名 ICP。

## 为什么这是最有价值的一步

现有 1,484 条评论已证「需求真实」，但没法告诉你他们要**推荐器还是规划器**。管家测试直接观察：当一个真人每晚把「明天穿这套」递到她面前时，她**实际穿不穿、改不改、要不要继续**。这三个数字比任何问卷都硬。

## 招募（用 `screener.md`）

- 8-12 名，25-45，职业，**大衣橱**（关键：`screener.md` 筛掉胶囊/极简自解者——他们是干扰项）
- 混合 dress code（正装/商务休闲/通勤）、气候（强季节 vs 稳定）、办公形态（在办/混合）
- 报酬：$25-40 礼卡 / 参与全程（或社区志愿者）

## 每日流程（每晚，每人 5-10 分钟）

1. **建档（第 0 天，一次性）**：每人拍 ~30 件常穿衣服发给你（微信/短信/共享相册均可）。你按品类+颜色+正式度粗标一张清单（就是 ClosetCore 的输入，你手动当引擎）。记录她的**身体维度可选**（测 H3 合身价值）。
2. **每晚（约 20:00）**：问她/查她次日日历有什么（会议/约会/在家）+ 查她所在城市**次日日间**天气（只看白天时段，别用夜间低温——这是竞品差评点）。
3. **手动组套**：从她的清单里挑一套（上装+下装或连衣裙+鞋，按场合正式度、天气、别重复她近 7 天穿过的、别撞色）。可参考 ClosetCore 的规则逻辑手动执行。
4. **发送**：一条消息「明天：[场合] + [天气]。建议：[单品清单] + 一句为什么」。**像 App 会做的那样**，别加人情味解释（测的是产品体验不是你的魅力）。
5. **记录到追踪表**（见下）。

## 追踪表结构（每人每天一行，用 Google Sheets）

| 字段 | 说明 | 对应验证指标 |
|------|------|------|
| date / participant | | |
| occasion | 当天场合 | |
| suggested_items | 你发的搭配 | |
| **wore_it** | 是否真穿了（次日问）Y/N/partial | **穿着率**（核心） |
| **override** | 改穿了自己选的？Y/N；改了什么 | **覆盖率**（推荐器 vs 规划器信号） |
| override_reason | 为什么改（不喜欢/不合场合/想自己选/合身问题） | 归因 |
| fit_comment | 合身反馈（紧/合/松）——若采了维度 | H3 |
| unsolicited_quote | 她主动说的原话 | 质性 |

## 判读（第 7 天 + 第 14 天）

| 信号 | 读法 |
|------|------|
| **高穿着率 + 低覆盖率 + 7 天后主动说「请继续发」** | 推荐器赌注成立 → GO 方向 |
| **高覆盖率**（常改穿自己的）或 **「我更想自己选，只要帮我看清有什么」** | → **PIVOT 到规划器**：把核心从「算法决定」改成「辅助规划」（你选场合→我帮你缩小范围） |
| 低穿着率 + 「其实我无所谓/本来就有一套」 | H1 可能是锦上添花 → 警惕 KILL |

**关键观测**：override_reason 里「想自己选」的频率，是推荐器 vs 规划器最直接的读数。

## 与 ClosetCore 的关系

你手动当引擎时用的规则，正是已建好的 ClosetCore（场合正式度/四条正确性/配色/体型加权）。**若判读为 PIVOT，这套逻辑不浪费**——降级为规划器的「帮你缩小范围」后端，过滤/语法/打分全保留，只是把「自动选一套」改成「给你几个合规选项，你定」。
