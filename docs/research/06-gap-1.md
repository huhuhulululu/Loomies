## 1. 中国大陆上架

### 1.1 ICP 备案：强制，且要求境内主体

- 政策原文：工信部《关于开展移动互联网应用程序备案工作的通知》（工信部信管〔2023〕105号，2023-08）：
  - 原文：https://www.miit.gov.cn/zwgk/zcwj/wjfb/tz/art/2023/art_920db564162e4312916a01bed6540ad8.html （政府网转载：https://www.gov.cn/zhengce/zhengceku/202308/content_6897341.htm）
  - 时间线：2023-09 起新 App 须先备案后上架；存量 App 宽限至 2024-03-31；2024-04 起对未备案 App 处置（下架）。
- Apple 执行（开发者论坛官方回复）：
  - 2023-09 起中国大陆 App Store 新 App 必须提供 ICP 备案号（https://developer.apple.com/forums/thread/743051）；
  - 2024-04-01 起无备案号的 App 无法发布更新并面临下架（https://developer.apple.com/forums/thread/743661）。
- 关键含义：**备案主体必须是中国境内主体**（个人可办非经营性备案，但商用/含支付一般需公司主体 + 可能的增值电信许可）。无境内主体的海外开发者事实上无法上架国区。
- 附加：AI 类 App 曾因「无在华运营许可」被批量下架（2023-08，https://zhuanlan.zhihu.com/p/647463118）——AI 功能上架国区还需 1.3 节的备案/登记证明。

### 1.2 PIPL：身体维度数据的定性与义务

- 《个人信息保护法》（2021-11-01 施行，全文：http://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm）：
  - 第 28 条：敏感 PI = 「一旦泄露或者非法使用，容易导致自然人的人格尊严受到侵害或者人身、财产安全受到危害的个人信息」，列举含**生物识别、医疗健康**等；
  - 第 29 条：处理敏感 PI 须取得**单独同意**；
  - 第 55 条：处理敏感 PI 前须进行**个人信息保护影响评估（PIPIA）**并记录；
  - 第 40 条：仅 CIIO 与「处理个人信息达到国家网信部门规定数量」的处理者有强制本地化义务——本 App 早期体量大概率不触发，但国区数据放境内（CloudKit 国区天然满足）是最稳妥路径。
- 细化标准 GB/T 45574-2025《数据安全技术 敏感个人信息处理安全要求》（2025-04-25 发布、2025-11-01 实施，国标信息：https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=F9F3A2EBF49E9B4D73AD8C8912986D5A；国浩解读：https://www.grandall.com.cn/ghsd/info.aspx?itemid=31297）：
  - 判定法：以「泄露后是否易致人格尊严/人身财产危害」实质判断，并明确**多项一般信息汇聚可升格为敏感**；
  - 敏感 PI 处理须在一般告知同意外**单独同意**（弹窗/独立页面），生物识别等场景须书面同意。
- **对本 App 的定性结论**：
  1. 身高/体重/三围等身体维度：未被法定或国标附录明确列为敏感 PI；但与「医疗健康」相邻、且与体型画像汇聚后敏感性上升 → **建议按敏感 PI 口径执行**（单独同意 + PIPIA + 最小化 + 端侧优先）。
  2. 未来「全身照」功能：照片中含**人脸 → 人脸信息属生物识别 = 法定敏感 PI**，单独同意为硬义务；产品上应引导拍摄不含人脸的全身照或自动打码。
  3. 衣物照片、位置标签（存放位置为家庭内位置描述，非行踪轨迹）为一般 PI。

### 1.3 生成式 AI / 算法备案 / 内容标识 / 深度合成

- 《生成式人工智能服务管理暂行办法》（2023-08-15 施行，原文：https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm）：
  - 第 2 条：向境内公众提供生成文本/图片等内容的服务即适用（企业内部自用豁免——本 App 面向公众，**适用**）；
  - 第 17 条：「具有舆论属性或者社会动员能力」的服务须安全评估 + 算法备案。
- 备案 vs 登记（关键实操口径，网信办 2025-09-10 公告：https://www.cac.gov.cn/2025-09/10/c_1759222982377536.htm）：
  - 自研/二次开发模型 → **备案**（安全评估材料等）；
  - **「通过 API 接口或其他方式直接调用已备案模型能力的生成式人工智能应用或功能，由地方网信办开展登记」**——本 App 的云端 LLM 搭配理由生成走这条：接已备案国产模型 + 向属地省级网信办**登记**（材料：服务协议、关键词库等）；
  - 规模参考：截至 2025-08-31 累计已备案服务 538 款、已登记应用/功能 263 款。
- 算法推荐备案：《互联网信息服务算法推荐管理规定》（2022-03-01 施行，原文：https://www.cac.gov.cn/2022-01/04/c_1642894606258238.htm）第 24 条备案义务**仅限「具有舆论属性或者社会动员能力」**的提供者——纯衣橱个性化搭配推荐一般不具舆论属性，理论上可不做算法备案；但 App Store 审核实践中 AI 功能常被要求出示备案/登记证明，从严准备。
- AI 生成内容标识：《人工智能生成合成内容标识办法》（四部门发布，2025-09-01 施行，原文：https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm）+ 强制国标《网络安全技术 人工智能生成合成内容标识方法》同步实施：AI 生成的搭配理由文案、体型可视化图像须加**显式标识**（页面提示）与**隐式标识**（文件元数据）。
- 深度合成：《互联网信息服务深度合成管理规定》（2023-01-10 施行，原文：https://www.cac.gov.cn/2022-12/11/c_1672221949318230.htm）。体型近似生成/虚拟试穿属「人体图像生成编辑」类深度合成场景；若涉及对**人脸、人体等生物特征编辑**，须显著标识并提示取得被编辑个人单独同意。用「参数化虚拟形象（非真人照片）」实现可视化可大幅降低适用面。

### 1.4 境外 LLM API 不可用与国产替代对比

- Google Gemini API：可用地区清单**不含中国大陆、香港、澳门**（含台湾）（https://ai.google.dev/gemini-api/docs/available-regions）。

## 2. Apple Intelligence / Foundation Models 在国行的可用性（决定端侧双轨架构）

- Foundation Models framework：iOS/iPadOS/macOS/visionOS **26.0 起**（watchOS 27 beta），端侧 + Private Cloud Compute，支持 @Generable 引导式结构化生成、Tool calling、图像附件多模态（官方文档：https://developer.apple.com/documentation/foundationmodels）。
- 可用性门控：`SystemLanguageModel.availability` 返回 deviceNotEligible / appleIntelligenceNotEnabled / 地区与语言不支持等原因——**框架可用性 = Apple Intelligence 可用性**，App 必须按枚举做运行时降级。
- 国行现状与时间线：
  - 国行（CH/A）iPhone 系统层面屏蔽 Apple Intelligence，即使人在海外也不可用；非国行设备在大陆可通过区域设置使用（媒体与官方支持口径汇总）。
  - 2025-02：苹果与阿里合作（Qwen）报道；简体中文语言支持已随 iOS 18.4（2025-04）就位，但国行设备仍被排除。
  - **2026-07-15：网信办公布新增备案，苹果端侧生成式 AI 服务完成备案**（备案主体：苹果技术开发（上海）有限公司，编号 Shanghai-AppleZhiNeng-202506160057；https://news.qq.com/rain/a/20260715A08JAA00；https://www.macrumors.com/roundup/apple-intelligence/）。
  - 媒体报道本次获批**仅覆盖 iPhone**（iPad/Mac/Vision Pro 暂不在列），阿里 Qwen 承担文本/图像理解与生成，百度参与（视觉搜索），已售国行兼容设备届时可激活；**预期 iOS 27 正式版落地，暂无确切上线日**（https://www.digitaltrends.com/phones/china-approves-apple-intelligence-for-iphones-with-alibaba-baidu-emerging-as-partners/）。
- **架构判定**：「端侧 FM 双轨推荐」在中国市场**方向成立、当前不可依赖**——今天（2026-07-21）国行用户 FM 不可用；乐观估计 iOS 27（2026 秋）后逐步开放且仅 iPhone。双轨必须实现为三态：FM 可用（端侧）→ FM 不可用（云端国产模型）→ 无网（本地规则引擎），且以 availability API 动态切换、不做静态区域假设。

## 3. CloudKit 与 WeatherKit 在国内

### 3.1 CloudKit（国区 iCloud = 云上贵州系运营）

- 中国大陆 iCloud 自 2018-02-28 起由云上贵州运营；现行运营主体为**云上艾珀（贵州）技术有限公司**（贵州大数据产业集团全资子公司），Apple 支持页：「iCloud 在中国大陆由云上贵州（云上艾珀（贵州）技术有限公司）运营」（https://support.apple.com/zh-cn/111754）。
- 中国账号的照片/文档/备份等 iCloud 数据存储于境内数据中心（贵安）。对开发者：CloudKit 容器对国区账号自动路由至境内环境，无需单独配置；App 隐私政策需披露该运营主体。
- 已知限制（实践口径，官方文档未系统披露）：国区与非国区账号分属不同分区，**跨分区的 CKShare 协作/公共库互通不可依赖**；用户未登录 iCloud 时同步不可用 → 本地 SwiftData/Core Data 为主、CloudKit 为同步层的架构更稳。
- 利好：走 CloudKit 意味着用户数据由 Apple/云上艾珀托管、开发者不自建服务器，可显著简化 PIPL 合规面（开发者仍是处理者，但无出境场景）。

### 3.2 WeatherKit

- WeatherKit 在中国可用；Apple 官方支持页确认「对于中国大陆，极端天气信息由『和风天气』提供」（https://support.apple.com/zh-cn/105038；数据源与署名要求：https://developer.apple.com/weatherkit/data-source-attribution/，需按页面要求展示数据来源署名与 Apple Weather 商标）。
- 限制：次小时（分钟级）降水等数据集在中国大陆覆盖有限/不可用；空气质量等字段按地区能力探测。社区亦有大陆访问稳定性抱怨（非官方）。
- 建议：天气→穿搭推荐用 WeatherKit 日级/小时级数据即可满足；对缺失字段静默降级，不做硬依赖。

## 4. 出海欧美（GDPR + 隐私标签）

- GDPR Art. 35 DPIA 触发（https://gdpr-info.eu/art-35-gdpr/）：(a) 基于自动化处理（含画像）对个人进行系统性、广泛评估；(b) 大规模处理 Art. 9 特殊类别数据；(c) 大规模公共区域系统监控。
- 定性：
  - 身体维度本身**不是** Art. 9 特殊类别（非健康数据，除非可推断健康状况）；
  - 照片**不自动**构成生物识别数据——仅当「通过特定技术手段处理、用于唯一识别自然人」才算（Recital 51：https://gdpr-info.eu/recitals/no-51/）。体型近似可视化不做身份识别 → 通常不落入 Art. 9；
  - 但「身体数据 + 全身照 + 自动化体型画像 + 女性用户群」组合命中 WP248 多项高风险准则（评估/画像、敏感性质数据、创新技术应用，EDPB DPIA 指南 WP248 rev.01：https://ec.europa.eu/newsroom/article29/items/611236）→ **上线前做 DPIA 是应然动作**；全流程端侧处理可把风险等级压到最低并简化 DPIA 结论。
- App Store 隐私标签口径（https://developer.apple.com/app-store/app-privacy-details/）：
  - 身体维度 → **Health** 类（定义涵盖 HealthKit API 及「任何用户提供的健康或医疗数据」；若坚持不算健康数据则落 Other Data Types——从严申报 Health 更稳）；
  - 衣物/全身照片 → Photos or Videos；搭配收藏/标签注释 → Other User Content；
  - 若数据仅端侧处理且不离开设备，可按「不收集」口径申报（须确保云端确实不经手）。
