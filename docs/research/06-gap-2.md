# 调研 06-gap-2：分层纸娃娃着装可视化的可行性与技术选型

> 日期：2026-07-21。调研方式：官方站点 / App Store / GitHub / 官方文档一手来源 + DuckDuckGo 检索兜底（本 session WebSearch 配额耗尽、exa key 失效，未能抓取应用内截图，效果证据以官方描述 + 第三方评测文字为主，附链接供人工核查）。

## 1. 核心问题

「把用户衣物的抠图照片，变形贴合到按身体尺寸生成的风格化 croquis（人体剪影）上」——是否有成功先例？若做，用哪档技术？

**一句话结论：没有找到任何主流产品用『真实衣物照片 2D 变形贴 croquis』路线成功的先例。市场分化为三条已验证路线：① 纯平铺拼贴（Stylebook/Indyx/Whering/Codibook）；② 生成式 AI try-on（Acloset 新版/Alta/FitCheck）；③ 统一插画风 avatar（PutTogether，衣物重绘为插画而非照片）。2D 照片变形贴合处于两头不靠的「恐怖谷中间带」，商业产品普遍绕开。**

## 2. 效果参照：竞品如何做

### 2.1 平铺拼贴阵营（无人体，已验证可用）

- **Stylebook**：自由画布上「捏合拖拽衣物抠图做杂志式拼贴」，提供背景移除滑杆 + 橡皮擦；官方功能页完全没有人台/croquis/avatar 概念。来源：https://www.stylebookapp.com/features.html
- **Indyx**：平铺 flatlay + 自动背景移除 + 造型师人工服务（Lookbook $150 起）；同样无 avatar。来源：https://www.myindyx.com
- **Whering / Cladwell**：第三方对比称 Whering「最佳 flat-lay 设计」，但「用户在构图中不可见」。来源：https://www.puttogether.world/guides/digital-closet/ai-outfit-app-that-draws-you-2026
- **Codibook（코디북，韩国）**：商品图拼贴（코디맵）+ 社区分享 + 导购，无人体模板。来源：https://www.codibook.net 、DuckDuckGo 检索结果

### 2.2 Avatar 阵营（2025–26 已集体转向生成式）

- **Acloset（Looko Inc.，700 万用户，App Store 4.4★/4.4K 评分）**：当前版本的 try-on 是「**单张全身照创建虚拟 avatar** → 在 avatar 上试穿衣橱衣物」——即生成式合成，而非把抠图照片贴到卡通人身上。来源：https://apps.apple.com/us/app/acloset-ai-fashion-assistant/id1542311809 、https://play.google.com/store/apps/details?id=com.looko.acloset 、https://www.acloset.app
- **Style DNA**：只做色彩分析 + 平铺搭配推荐 + 导购，官方站**无** avatar/try-on 可视化。来源：https://styledna.ai
- **Alta**（$11M 融资）：脸照 + 身体尺寸渲染照片级 avatar，定位「fit validation」。来源：puttogether 对比文（上链）
- **FitCheck AI / DrapeAI / Google try-on**：均为生成式 AI 试穿。来源：DuckDuckGo 检索结果
- **PutTogether**：刻意选择**水彩插画风 avatar**（衣物被重绘成插画），并声称内部研究显示「插画 avatar 被评为比照片级更讨喜（more flattering）」。注意：该对比文出自 PutTogether 自家博客，对自身有利，需打折。来源：https://www.puttogether.world/guides/digital-closet/ai-outfit-app-that-draws-you-2026

### 2.3 换装游戏（dress-up game）的真相

Unity 生态的 paper doll 系统（DressUp Template、Paper Doll System 等）全部基于：**美术按同一套标准体型模板预先绘制每件衣物素材，运行时只做图层槽位（slot）替换 + 锚点对位**，不存在对任意照片的变形。视觉质量好是因为素材天生合身——这条经验**不可迁移**到「用户任意拍摄的衣物照片」，但其「锚点 + 图层槽位（发/上装/下装/鞋分层、z-order）」架构值得直接抄。来源：DuckDuckGo 检索（Unity Asset Store DressUp Template、WillyXZ Paper Doll System 等）

### 2.4 「按尺寸生成 croquis」有独立的成功先例

**MyBodyModel**：输入身体测量值 → 生成个人化 croquis 模板（JPEG/PDF 付费下载），面向缝纫/编织/cosplay 人群；上过 Sew News、Seamwork、Love to Sew 播客，Kickstarter 成功。证明「尺寸参数化 croquis」本身有真实付费需求——但其用途是**手绘**设计，不是照片贴合。来源：https://www.mybodymodel.com

### 2.5 小结（对应任务问题 1）

「真实衣物抠图 + 风格化 croquis」= 无成功大众先例；产品要么停留纯拼贴，要么直接跳到生成式。中间带唯一可辩护的做法是**设计语言统一化**：把照片处理成卡片化/统一阴影/描边的「半插画」贴在 croquis 分层槽位上，明确示意性、不承诺合身感（详见 §5 三档定位）。

## 3. 贴合技术路线对比（对应任务问题 2）

| 路线 | 原理 | iOS 实现 | 许可 | 效果上限 | 工程量 |
|---|---|---|---|---|---|
| A. 刚性缩放+锚点 | 按 croquis 槽位（肩宽/腰位/臀位）等比缩放 + 平移，衣物不变形 | 纯 SwiftUI/Core Graphics，锚点为 croquis 参数化输出 | 无第三方 | 「纸娃娃示意」；照片与剪影比例正确但不贴体 | ~1-2 周 |
| B. 关键点仿射/分段仿射 | 衣物 3-5 关键点（左右肩、下摆两端）→ croquis 对应锚点，做整体仿射或上下两段仿射 | Core Graphics `CGAffineTransform` / Core Image；关键点来自 §4 | 无第三方 | 肩线对齐、裙摆角度自然；无法表现腰身曲线 | +1-2 周 |
| C. TPS / 网格变形 | 衣物 N 个关键点 ↔ croquis N 个锚点，薄板样条求密集形变场，衣物随体型曲线弯曲 | 见下三条 | 见下 | 贴体感最好，但对关键点误差极敏感，易出「橡皮泥」伪影 | +3-6 周（含调参） |

### 3.1 TPS 在 iOS 的三条落地路径

1. **OpenCV shape 模块**：`cv::ThinPlateSplineShapeTransformer`（`estimateTransformation` / `warpImage`，带正则化参数 β 控制平滑）。OpenCV **4.5.0 起 Apache-2.0**（4.4 及以前 3-clause BSD），商用友好；经 SPM/CocoaPods 集成 iOS。来源：https://docs.opencv.org/4.x/dc/d18/classcv_1_1ThinPlateSplineShapeTransformer.html 、https://opencv.org/license/
2. **Swift 自实现 TPS + SpriteKit 网格渲染**：TPS 是封闭形式线性方程组（Bookstein），可用 Accelerate/LAPACK 在 CPU 求解 → 输出网格目标点 → 喂 `SKWarpGeometryGrid(columns:rows:source:destination:)`（iOS 10+，GPU 加速，可动画）。**未找到现成 Swift TPS 开源库**，需自己移植（参考 MIT 许可的 numpy 实现 https://github.com/raphaelreme/tps ）。来源：https://developer.apple.com/documentation/spritekit/skwarpgeometrygrid
3. **Core Image `CIWarpKernel` / Metal 自定义 mesh**：完全自控但工程量最大；Core Image 无内置 TPS。

### 3.2 学术界（VITON 系）给出的天花板参照

- **CP-VTON**（MIT 许可）：学习式几何匹配（GMM，TPS 参数由网络回归）+ 融合模块；输入需要**人像照片 + OpenPose 姿态关键点**，且以真人照片为目标——与本 App「贴到插画 croquis」场景不同构。来源：https://github.com/sergeywong/cp-vton
- KF-VTON、RT-VTON 等后续工作转向 keypoint-driven flow / 半刚性形变；第三方汇总称此类开源 try-on「多为非商用许可」，选型时逐仓核查。来源：DuckDuckGo 检索结果
- 结论：**纯几何 TPS（不加神经修补）在真人照片上都难消伪影，贴到插画 croquis 只会更突兀**——这正是商业产品绕开该路线的技术原因。

## 4. 服装关键点检测端侧方案（对应任务问题 3）

### 4.1 数据集与许可

- **Fashionpedia**：48,825 图，27 主类 + 19 服装部件（领/袖/下摆等）的**分割掩码** + 294 细粒度属性。**标注与本体 CC BY 4.0（可商用，需署名）；图像版权归各来源平台（Flickr/Unsplash/Pexels 等），需按各平台条款自查**。注意：**它没有现成关键点标注**——肩点/领口/腰线/下摆需从部件掩码几何推导（如袖-躯干掩码交界=肩点），可行但要写派生管线。来源：https://fashionpedia.github.io/home/index.html 、https://fashionpedia.github.io/home/data_license.html
- **DeepFashion2**：13 类 × 共 294 个服装关键点、49 万图——标注最对口，但**下载需填表拿解压密码（受控分发），未公开明确商用许可**；商用训练有法律风险，不建议作为商用模型的训练底座。来源：https://github.com/switchablenorms/DeepFashion2
- 早期 DeepFashion fashion-landmarks（8 关键点，Caffe 时代）：https://github.com/liuziwei7/fashion-landmarks ；轻量方向有 DeepMark++（WACV 2021，边缘端实时）。检索未发现「现成、轻量、明确可商用」的预训练服装关键点模型——**自训不可避免**。
- ⚠️ 若自训选 Ultralytics YOLOv8-pose：**AGPL-3.0**，闭源商用需买企业许可——建议改用 MobileNet/timm 骨干 + heatmap 头自训后转 Core ML。

### 4.2 Vision 框架反向复用评估

- `VNDetectHumanBodyPoseRequest`（iOS 14+，19 个人体关节点）：检测**人体**，对平铺/挂拍的无人衣物照**不适用**；正确用途是（可选）从用户全身照提取比例校准 croquis。来源：https://developer.apple.com/documentation/vision/vndetecthumanbodyposerequest
- 抠图：`VNGenerateForegroundInstanceMaskRequest`（iOS 17+ 主体抠像）/ VisionKit subject lifting（iOS 16+）——衣物抠图零成本原生解决。来源：https://developer.apple.com/documentation/vision/vngenerateforegroundinstancemaskrequest
- **无 ML 备选（MVP 推荐）**：本 App 拍摄场景受控（引导用户平铺/挂拍、正面朝上），抠图后用 `VNDetectContoursRequest` + 轮廓几何启发式（凸包极值点、曲率角点）即可定位肩点/下摆/腰宽，配合**用户可拖动微调锚点**的 UI 兜底。这条路零训练成本、无数据集许可问题，且换装游戏证明用户能接受手动摆位。来源：https://developer.apple.com/documentation/vision/vndetectcontoursrequest

## 5. 三档保真度对比与建议（对应任务问题 4）

| | Tier 1 纯拼贴示意 | Tier 2 锚点缩放贴 croquis | Tier 3 变形贴合（TPS/网格） |
|---|---|---|---|
| 视觉承诺 | 「搭配组合」不承诺人身效果 | 「比例正确的纸娃娃示意」 | 「近似贴体」 |
| 市场先例 | Stylebook/Indyx/Codibook，充分验证 | 换装游戏（预制素材）+ MyBodyModel（croquis 本体）；照片版无直接先例 | 无商业先例；学术 VITON 需真人照+神经修补 |
| 关键点需求 | 无 | 3-5 点（可启发式+手调） | 8-16 点（需模型或大量手调） |
| 失败模式 | 无（底线方案） | 比例/层叠错觉小；照片风格与剪影风格冲突 | 橡皮泥伪影、图案拉花、恐怖谷 |
| 依赖许可 | 系统 API | 系统 API | OpenCV Apache-2.0 或自研；训练数据许可复杂 |
| 预估工程量（AI 辅助） | ~1 周 | ~2-4 周（含 croquis 参数化） | +4-8 周且效果风险高 |

**推荐：MVP = Tier 1 + Tier 2 同时提供**（拼贴视图给「搭配管理」，croquis 视图给「体型示意」），Tier 3 只做 feature-flag 实验不进主路径；若未来要高保真，直接接**服务端生成式 try-on**（市场已验证方向），跳过打磨 2D 变形。

### MVP 验收标准建议（pass/fail）

1. 衣物入库：iOS 17 原生抠图成功率 ≥90%（受控拍摄引导下），失败可手动补抠。
2. croquis：由 ≥4 项身体维度（身高/胸/腰/臀）参数化生成，同一衣物在两档体型上呈现可辨差异（肩宽/腰位横向偏移 ≥5%）。
3. Tier 2 贴合：上装肩线中点与 croquis 肩锚点偏差 ≤ 衣宽 5%；用户可拖拽/缩放微调并持久化保存。
4. 分层：上装/下装/外套/鞋 z-order 正确，外套遮挡上装下摆。
5. 渲染性能：6 件衣物成套渲染 ≤1s（iPhone 12 及以上），无明显掉帧。
6. 风格统一：衣物卡片统一白底/阴影处理，croquis 为单色剪影——用户测试中「不觉得怪异」≥70%（5 人以上小样本即可）。

## 6. 关键风险与未决事项

- 效果截图未能程序化抓取（检索配额限制），上线前建议人工体验 Acloset avatar try-on 与 PutTogether，确认「生成式 vs 插画」两条路的实际观感。
- puttogether.world 的横评出自竞品自家博客，其「插画更讨喜」结论需独立用户测试复核。
- Fashionpedia 图像版权按来源平台各自条款——若自训模型，训练行为通常低风险，但发布 demo 图需用自有素材。
- DeepFashion2 许可不明——商用训练前须邮件确认或放弃。
