## 0. 决定性发现（先读这条）

**R1 的「需求」被证实是真的，但项目押注的「机制」是最悬的一环——这是潜在转向信号。**

- ✅ **需求真实（~80% 置信）**：职业女性确实按周/日历节奏预先规划穿搭、看天气——在精确 ICP（r/AskWomenOver30）直接观察到 5+ 条「周日把一周穿搭都摆好」，Indyx/Alta 好评印证（"no longer late to work figuring out what to wear"）。**R1 在需求层面已解决：是真需求，不是伪需求。**
- ⚠️ **但项目押的不是需求，是机制（~55% 置信）**：一个**自主的 场合/日历驱动推荐器**。这是最脆弱、最高风险的元素，本轮研究把风险锐化了：
  1. ICP 主要靠**手动**（周日规划）或**做减法**（胶囊/制服）解决——两者今天免费且有效，App 必须打赢「物理 + 免费」；
  2. 每个自主日推荐器竞品（Cladwell）都收「算法学不会」1★，而被爱的（Indyx、Alta 日历）是当作**手动策展 + 日历工具**用（"positioned as a creation tool, not a recommendation engine"）；
  3. 场合推荐只在**用户自己给出场合**时被夸（"going out for sushi"）——即作为**筛选/提示**，不是自主驱动。
- **真正的 R1 问题**：不是「有没有需求」，而是「他们想要**算法替他们决定**，还是一个**帮他们自己规划得很爽的工具**？」
- **关键筛选洞察**：需求按衣橱哲学分裂。靠**做减法**解决决策疲劳的人（胶囊/制服/"只穿黑"）是**干扰项，不是 ICP**；ICP 是「衣橱大、记不住/用不上、想显得得体」的人。任何不筛掉前者的验证都会误读信号。

**→ 这直接影响 DESIGN 的核心机制定位。验证的头号任务就是回答「推荐器 vs 规划器」。**

### 📊 方法④已执行，先验已锐化（v1.1，详见 §8）

方法④（竞品社区信号挖掘，AI 已跑）**独立于 App 评论用第三类证据（DIY 制品、付费足迹、Reddit 行为）印证了 §0**，且经对抗核查确认方向、修正幅度：

- **天平约 7:1 倒向「规划器/copilot」**（对抗核查修正：原声称 3-4:1 低估了——自主推荐器 App 差评率 ~51% vs 规划器/编目 App ~7%，`<=2★`）。用户描述理想解法时「帮我自己规划、看清我拥有什么」压过「替我决定」。
- **赢家机制是 copilot**（用户掌舵、App 跑腿）：「我选几件→AI 补全」被爱，「给一件就自动成套」被恨到退订。这正是 V2 落地页「You decide, it does the legwork」已编码的形态。
- **关键细化（对抗核查）**：**不是「自主推荐」本身有罪，是「naive 算法替你决定」有罪**。Alta（日 AI 推荐器却 4.88★、仅 8% 差评）证明——包装成用户掌舵的 copilot、天气/场合执行正确的日推荐器仍能赢。所以 V1 纯推荐器 hero 是高风险赌注，V2 规划器 hero 是更安全先验。
- **先验（非定论）**：预期 A/B 里 V2 规划器 hero 不输甚至赢 V1 推荐器 hero，落 §2 的 **PIVOT 带**。但**落地页 A/B 尚未真跑，这是强预期不是既成事实**——方法②仍是最终裁决器。

## 1. 四假设证据强度（本轮深化）

| 假设 | verdict | 置信 | 要点 |
|------|---------|------|------|
| **H1 场合/天气每日推荐** | 需求 strong / 机制 medium | 需求~80% / 机制~55% | 见 §0。需求硬、机制悬。验证优先打这个 |

| H4 不卡件数 + 隐私 | **weak（作获客差异）** | ~80% | 不卡件数=生存必需但非差异（Whering/Indyx/Alta 已都免费无限=入场券）。隐私有真实但**稀有**需求（仅少数成熟 Reddit 用户对某 App）——作信任/留存资产与 earned media 角度，非获客钩子 |

**最硬**：H1 的需求。**最悬（决策关键）**：H1 内部的「推荐器 vs 规划器」歧义——整个产品指向它。

## 2. 北极星验证指标与决策规则

**北极星** = **合格访客的付费承诺率**（qualified-visitor costed-commitment rate）：落地页上，经画像验证的 25-45 职业女性中，做出**真实付费动作**（可退定金 / $15 终身预购、仅上线时扣款）来预定「日历+天气日推荐产品」的比例。选它因为**定金是揭示性偏好**，而邮箱/问卷「yes」是陈述性偏好（现有 1,484 评论已覆盖陈述性需求）。

**骑在其上的 R1 判别器** = **A/B 提升比**：场合-日历 hero（V1）转化 ÷ 通用衣橱 hero（V2）转化——这**单个数字**说明「场合/日历」是不是楔子，还是只是通用衣橱的新鲜感。

**确认性第三关** = Sean Ellis「非常失望」≥40%（对日推荐这个 job，proxy 人群）。三者须相互印证；**揭示性（定金、A/B 提升）在任何冲突上压过陈述性（Sean Ellis）**。

### 决策规则

| 结论 | 判据（须同时满足） |
|------|------|
| **GO**（把场合/日历日推荐作**核心**建） | 邮箱转化 ≥10% 合格访客 **且** 付费承诺 ≥2.5% **且** V1/V2 提升 ≥1.5× **且** Sean Ellis ≥40% **且** ≥8/15 访谈显示**反复出现、当前有成本、场合驱动**的穿衣痛点且有失败的 workaround（过去行为，非陈述兴趣） |
| **PIVOT**（真需求、错楔子） | 邮箱 ≥10% 但 V1/V2 提升 <1.2× **或** Sean Ellis 25-40% **或** 访谈显示痛点是**泛泛决策困难而非场合特异** → 保留日推荐但把「场合/日历」从 hero **降级**，改测研究记录的 #1 JTBD（「记住我拥有什么」/防重复购买，19 次自发提及）作楔子，再投工程 |
| **KILL**（H1 不是这个赌注） | 邮箱 <5% **且** 付费承诺 <1% **且** Sean Ellis <25% **且** 访谈被「锦上添花，不会改行为或付费」主导 → 不把场合推荐作核心，重审产品命题 |
| **MIXED**（落在带间） | 延长广告投放到 n≥800 合格访客再决定；付费承诺率与 V1/V2 提升是 tie-breaker |

### 砍项/转向触发信号（任一出现即警报）

- 付费承诺 <1%（≥400 访问后）——点击是好奇，无人掏钱，揭示性偏好缺席
- **V1（场合 hero）打不赢 V2（通用 hero），提升 <1.2×**——场合角度不是驱动器，R1 的具体赌注为假（**最决定性的 kill/pivot 触发**）
- Sean Ellis <25%——job 本身缺乏拉力
- 访谈多数把早晨穿衣说成「已解决/低风险」（制服、胶囊已够），或有热情但**过去零时间零金钱投入**——Mom Test 恭维陷阱
- 获取一个付费承诺的混合 CAC > ~$25（对 $4.99 买断 / $30-50/年 LTV）——即使真需求也无法在小团队 ~$10⁵ ARR 单位经济下回本
- 主导有机信号是**替代**（"我做减法/胶囊解决了"）而非**工具 hacking**——免费行为 workaround 打赢产品
- 招不到 ≥40 真 proxy 用户或 ≥400 真合格访客而不靠造假/马甲——目标人群太薄，无法诚实验证

## 4. 现成 instrument（可直接用）

### 4.1 访谈脚本（Mom Test，非诱导）
- **招募伪装**（内部，不给受访者看）：作为「职业女性如何应对早晨与穿衣」研究招募，**不是**「衣橱 App」研究（点名 App 会把样本偏向 App 爱好者，毒化 R1 测试）。N=12-15，配额混合：~1/3 试过衣橱 App 并弃用、~1/3 自认已解决（胶囊/制服）、~1/3 自述挣扎。$25-40 礼卡/30 分钟。
- **R1 头号陷阱**：创始人**想要**「场合」是答案，所以访谈员**绝不能**植入——不说 occasion/calendar/weather/meetings/dress code 任何词，让它自己冒出来。
- **问题**（问过去真实行为，不问未来假设意愿）：
  1. 带我过一遍今早（或上个工作日早晨）——从开始想穿什么到出门，实际发生了什么？
  2. 那是典型的一天还是更难/更易？说说上一个真正挣扎的早晨。
  3. 这种早晨多久一次？最近一次是？
  4. 难的早晨你实际怎么脱困？
  5. 过去一年你试过什么让这件事更轻松——从改习惯到买东西到试 App？
  6. 试过又停掉的，什么让你停？大概何时弃用？
  7. 你为这事花过真金白银吗（造型师/清衣橱/订阅盒/付费 App）？走一遍最近一次付费，值不值？
  8. 一周里有没有某些日子/场合你更花心思穿？说说最近一次和它的不同。
  9. 上次站在满衣橱前还觉得「没衣服穿」，回头看那到底是什么？
  10. 当你确实定下一套满意的，通常是什么让它那天成立？
  11. 你身边有谁看起来完全搞定了这事——你觉得他们做了什么你没做的？
  12. 关于工作穿衣，有什么我该问没问的？

## 8. 方法④结果（AI 已执行，2026-07-21）

> 完整报告 `docs/research/18-method4-signal.md`（410 行，一手引用带来源+日期）。数据源：pullpush.io Reddit API + iTunes RSS（WebSearch/exa 本轮失效，靠这两个）。四条线同向，决定性断言经对抗核查 **confirmed**。**方法④是最早最便宜的信号，单独不能定 GO/KILL，但强烈锐化了先验方向；最终裁决仍是方法②的 A/B。**

### 8.1 推荐器 vs 规划器（决定性，核查 confirmed）
- 两个独立一手语料同向：理想解法「帮我自己规划/看清我有什么」以约 **7:1**（差评率口径）压过「替我决定」。
- 口碑最强两款（Stylebook $4.99 买断无推荐器、Indyx 日历策展）是**纯规划器**；被弃用的自主日推（Cladwell「algorithm refuses to learn」/Acloset）差评集中在推荐质量。
- **赢家=copilot**：「我选几件→AI 补全」被爱，「给一件就自动成套」被恨到退订（Acloset 2★ 直接因此「will not renew」）。
- **细化**：naive autopilot 才有罪；Alta（日推荐器 4.88★）证明**执行正确+用户掌舵框架**的日推荐器能活。
- 差评率硬数据（iTunes，同采样 250 条/App，相对差有效）：自主推荐器组 Cladwell 53%/Pureple 50%/Acloset 49%/Smart Closet 51%（均 ~51%）vs 规划器组 Stylebook 16%/Indyx 4%/Whering 0%（均 ~7%）。

### 8.2 DIY 群体（third 独立证据，偏规划器）
- 手动提前规划是**主流大众行为**（"plan my outfits" 4 个月 100 条/95 独立线程/84 子版），数字自建衣橱（Notion/表格）是**小而铁杆 power-user 利基**。
- 两层**清一色自建规划器/追踪器,几乎无人自建推荐器**——独立于 App 评论的第三类硬证，继续偏「规划器」。

### 8.3 付费意愿（真实但窄）
- 付费意愿几乎只存在于 **$4.99 买断**；免费采用速度约 **13×**（Alta 16 月 10,783 评分 vs Stylebook 16 年 8,701）。
- 项目押注机制最像的 Cladwell（自主订阅推荐器）是老牌里 footprint 最小/均分近最低——**该机制已是付费毒资产**。
- **对 §2 校准**：≥2.5% 付费承诺阈值**只在用买断框架测时可守**；最大最有钱的玩家（Alta/Whering）故意不向用户收费、改走购物佣金=资本判定直接向用户收费太薄。

### 8.4 ICP 筛选（决定招募质量）
- ICP vs 干扰项**须按行为标记（是否已做减法消灭问题）筛，非态度问卷**。
- **三分而非二分**：真干扰项=极端精简者（自述已解决、明确不用 App）；胶囊社区里有一支 **App 化策展者=缩小版 ICP 非干扰项**（naive「你用衣橱 App 吗」会误混）；ICP 本体语言=大衣橱+忘记拥有+重复购买+满柜「没得穿」+想得体，**ADHD object permanence 是最锋利的自我描述轴**。
- → `validation-kit/screener.md` 的第 6/8 题正是按此设计。

### 8.5 方法④对决策的净含义
- **先验从「悬」变为「强烈偏 PIVOT/copilot」**：产品核心机制大概率应是 **copilot（用户掌舵、App 跑腿，full-auto 作可选开关）**，而非 autopilot（算法替你决定）。
- **但不改「先验证再大投入」的结论**：方法④是揭示性观察非实验，且社区（r/FFA）过采样掌控派、pullpush 覆盖止于 ~2025-05——**方法②落地页 A/B 的 V1/V2 提升比仍是最终裁决器**。
- **可执行校准**：当前 V1 文案「from the clothes you already own」已带掌控味、非纯 autopilot，会稀释 A/B 信号——投放时 V1 应更硬地测「纯自动决定」才能干净隔离自变量（`landing-deploy-guide.md` 已注）。
- **对已建代码零浪费**：ClosetCore（78 tests）在 copilot 形态下全部复用——把「自动选一套」改成「给你几个合规候选、你定」，过滤/语法/打分/体型加权/尺码全保留。
